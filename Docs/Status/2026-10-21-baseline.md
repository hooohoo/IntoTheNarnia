## 기존 구조의 문제

GameManager 정적 접근과 FieldManager 수동 Init 순서에 의존합니다. Professor_House 단독 실행 경로가 없습니다. 씬 참조 해제와 Cinemachine 전역 입력 델리게이트 복원이 없습니다. FileIOManager는 Assets 경로에 직접 접근하며 다시 Init할 때 대화를 중복 누적합니다. QuestManager는 씬마다 상태를 초기화하고 문 영역 비트에 더하기 연산을 사용합니다. 도메인 로직이 Update와 UI에 분산되어 있습니다.

기존 문서는 다른 프로젝트의 Flutter/URP/HexGrid/Addressables 및 dev 흐름을 설명하고 있었습니다. 이번 문서 기준선은 실제 상태와 승인된 구조 전환 목표를 분리합니다.
