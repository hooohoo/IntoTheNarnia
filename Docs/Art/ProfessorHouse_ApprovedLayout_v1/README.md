## 기준의 우선순위

공간 배치와 높이·접속 관계는 이 폴더의 `Data/layout.json`과 도면을 따른다. [기존 승인 보드](../ProfessorHouse_DesignReview_v1/index.html)는 형태·재질·분위기 참고로 유지한다. 기존 보드 묶음의 평면도, 2층 +3.60m·다락 +7.20m 수치와 초기 방 배치는 이번 확정안으로 대체한다.

[v2 구현 문서](../ProfessorHouseV2.md)는 현재 Unity 씬과 기존 생성 도구의 상태 기록이다. 그 문서의 18단 계단·+3.65m 회랑·두 문의 배치를 새 도면의 구현 완료로 해석하지 않는다. 기존 다운로드 3D 검토 04 역시 전체 확정 도면을 적용하기 전 모형이다.

## 층별 배치

| 층 | 확정 내용 |
| --- | --- |
| 1층 | 현관·홀·응접실·공용 도서실·음악실·식당·관리 공간. 서쪽 정원에 면한 D1 유물 전시실에서 창문·갑옷 사고가 일어난다. |
| 2층 서쪽 | 교수의 서재·침실·개인 서고 등을 전용 구역으로 묶는다. 공용 회랑과 연결되는 경계문은 한 곳이며, 아이들의 주요 동선은 내부를 통과하지 않는다. |
| 2층 동쪽 끝 | 동측 긴 회랑을 돌아 여자아이·남자아이 침실로 안내한다. 침실 복도와 보조 계단 S2 사이에 지름길 문을 만들지 않는다. |
| 다락 | S2 → 도착 전실 → 높은 홀 위 목재 복도 → 서쪽 꺾이는 복도 → G2 옷장방. 도착하자마자 옷장이 보이지 않도록 접근 방향을 유지한다. |

회랑 끝은 문·창가·끝벽·붙박이장으로 목적을 설명한다. 후정 앞 창가 공간을 다른 날개로 연결하기 위해 정원을 가로지르는 복도를 추가하지 않는다. 회색 사선으로 표시한 지붕 공간은 내부 미설계 영역이다.

## 세 장면의 동선

1. **첫 안내**: 주 계단의 왼쪽 갈래로 2층 서측 회랑에 올라 교수 구역 경계문을 가리키며 경고한다. 전면 연결 복도 → 동측 회랑 → 외진 아이들 침실로 이동한다.
2. **숨바꼭질**: 2층 놀이 공간·빈 손님방·공용 방·회랑을 탐색하고 S2를 찾아 다락으로 오른다. 꺾이는 복도 끝에서 옷장방을 처음 발견한다.
3. **창문·유물 사고**: 서쪽 정원의 공이 1층 D1 창을 깨고 갑옷의 투구·팔 장식 일부를 떨어뜨린다. 아이들은 별도 정원문으로 C1 응접실에 들어가 전시실의 파손을 확인한다. 유물에 대한 경고와 응접실 쪽 발소리에 놀라 D1 안쪽 아치 → 홀 → 동측 연결부 F0 → S2 → 다락의 익숙한 길 → 옷장방으로 함께 피신한다.

공이 지나가는 창과 사람이 들어가는 문은 서로 다른 개구부다. 갑옷 몸체는 받침에 남긴다. 음악실은 음악·휴식 공간으로 유지한다.

## 계단과 정원

도면 단위는 m, 외곽 기준은 50 × 34m다. 방위는 게임 설계용 도면 기준이며 영화 촬영장의 실제 방향을 뜻하지 않는다. JSON의 평면 좌표와 층 높이는 별개이므로 Blender/Unity 좌표 변환은 후속 제작 도구에서 명시한다.

| 높이/연결 | 기준 |
| --- | --- |
| 1층 / 공통 계단참 | +0.00 / +1.80m |
| 오른쪽 중간 계단참 / 2층 | +3.24 / +4.32m |
| 높은 홀 천장 / 다락 바닥 | +8.84 / +9.00m |
| 주 계단 | 공통 10단 후 왼쪽 14단, 오른쪽 8단 + 꺾임 + 6단. 단높이 0.18m. |
| S2: 1층 → 2층 / 2층 → 다락 | 12+12단 / 13+13단. 단높이 0.18m. 층마다 같은 평면 위치. |
| 후정 | 아치창 너머 하늘이 열린 정원. 상층 방·복도·지붕으로 덮지 않는다. |
| 동측 중정 | 모든 층에서 비어 있는 야외 공간. |

서쪽 정원 표시는 공놀이 장면에 필요한 일부 영역이며 저택 부지 전체의 경계가 아니다. 주요 비례·계단 분기·방 위치·접근 방향을 유지하며 벽 두께·마감·난간 접속·캐릭터 통행·카메라·머리 공간은 모델 단계에서 검증한다. 방 배치나 서사 동선을 바꾸는 수정은 새 도면 검토로 기록한다.

## 모델과 씬 제작에 적용

전체 배치는 연결 검증을 위한 공통 기준으로 유지하고, 제작 메시는 방·벽면·계단 단위로 나눈다. 문·옷장 문·파손할 갑옷 부속은 독립 오브젝트로 둔다. 씬 전환 여부와 로딩 경계는 후속 구현에서 정하되 도면의 문 위치와 이동 관계를 유지한다. 이 도면 승인이 모든 공간을 하나의 런타임 씬으로 로드하도록 확정한 것은 아니다.

후속 제작은 층 높이와 주/보조 계단을 포함한 연결 블록아웃 → 구역별 통합 메시와 개구부 → 실제 이동·카메라 확인 → 디테일·재질 순서로 진행한다. Lucy 신체 비율과 세부 모델은 별도 후속 범위다.

## 파일과 재현

- PNG 6장·SVG 6장·PDF는 사용자가 확인한 검토 03 원본을 그대로 보존했다. 이미지 안의 검토 번호는 승인 출처다.
- `Data/layout.json`이 확정 데이터다. `Data/layout_01.json`은 생성 스크립트의 과거 입력 자료이며 현재 설계 기준이 아니다.
- `Source/build_data.py` → `Source/build_figures.py` → `Source/build_page.py`는 Python 표준 라이브러리로 JSON·SVG·내장 지도·HTML을 생성한다. `python3 -B Source/validate_layout.py`로 도면 연결을 검사한다. 생성 명령은 해당 파일을 덮어쓰므로 새 작업본에서 실행한다.
- PNG·PDF는 승인 당시 브라우저 출력물을 보관한다. 재출력은 별도 작업본에서 수행하고 검토 원본을 조용히 바꾸지 않는다.
- `Data/browser-checks.json`과 `Data/export-checks.json`은 검토 03 시점 결과이며, `Data/Provenance/review03-delivery-manifest.json`은 당시 Downloads 전달 기록이다. 현재 승인 정보와 원본 일치 결과는 `ProjectApproval.json`을 따른다.
- 이 폴더는 제작 문서다. PNG와 PDF는 Git LFS로 관리하며 Unity/Addressables에 등록하지 않는다.

도면 검증은 50개 공간·54개 문, 12개 경로·29개 문 통과, 방/정원 겹침 없음과 S2 정렬·단높이 일치를 확인했다. 실제 Unity 이동·충돌·구조 안전성 검증을 대신하지 않는다. 영화 참고와 게임용 배치의 구분 및 출처는 [도면 화면](index.html)에 보존했다.
